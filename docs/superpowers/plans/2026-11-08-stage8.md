# Stage 8 and bonus features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Complete Notion stage 8 and its four bonus items with verifiable VM evidence.
**Architecture:** Keep existing routing and token fencing. Add independent monitoring/ETA, a read-only staff page, a bounded host-side scaling experiment and optional TLS proxy.
**Tech Stack:** Django 5.2, PostgreSQL, Celery/Redis, Docker Compose v2, Caddy, NFS.
**Spec:** docs/superpowers/specs/2026-11-08-stage8-design.md

## Global Constraints

- main workspace; no commits/pushes without separate request.
- Simple HTML, owner-only job endpoints, no Docker socket or secrets in web pages.
- Existing two VM data and volumes preserved, real conversion and evidence required.
- One worker process per node; default ETA 60 seconds and last 50 successful samples.
- Extra node pool contains only node-3; hard cap 3, max-nodes=2 disables expansion.
- Private local CA; do not alter Mac system trust automatically.

## Review Focus

- Stale/cooldown nodes and missing historical durations must not give false exact ETA.
- Old token, retry and cancellation must not overwrite timing or publish stale results.
- Non-staff and anonymous access must not expose cross-user operational data or secrets.
- Malformed telemetry, simultaneous controllers and cap=2 must never start extra services.
- Proxy spoofing and TLS cookie/CSRF behavior must keep login usable and HTTP backend private.
